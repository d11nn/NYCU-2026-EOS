# A. 怎麼做的

## A1. 題目與評分

講義 3.2：給一張隱藏照片（JPG，最大 6000×4000），在板子上 20 分鐘內跑完，**只框有戴安全帽的人**，用 HDMI 顯示並存成 JPG。3.2.1 的分數 = 50 × F1。

| 講義的規則 | 我們對應的設計 |
|---|---|
| 框到沒戴安全帽的人或背景，算 FP | 模型只學一個類別「戴在頭上的安全帽」。一般帽子、沒戴的安全帽、沒戴帽的人都當負樣本拿去訓練（A4） |
| 同一個人重複框，算 FP | NMS 之後再做一次「包含去重」，一人只留一框（A9） |
| 漏掉戴安全帽的人，算 FN；照片可能大到 6000×4000 | 大圖除了整張跑一次，再切塊各跑一次，補遠處的小帽子（A9） |
| 20 分鐘內跑完 | 時間很寬鬆，所以選比較準的模型和比較大的輸入（A3） |
| 圖片不可變形 | 存檔用原尺寸；顯示時等比例縮放、置中 |

## A2. 整體作法

```
公開資料集 ─▶ 統一成一個類別「戴在頭上的安全帽」─▶ 自動標註 + 交叉檢查 + 抽樣檢查 ─▶ 訓練集 58k 張
                                                                    │
                     val（挑門檻）、test（只用來確認）◀──────────────┤
                                                                    ▼
                                                   訓練 YOLO26s（輸入 640，60 epoch）
                                                                    │
            用講義的 TP / FP / FN 規則算 F1 ─▶ 信心門檻 0.50 ─▶ 看錯誤 ─▶ 校正分數
                                                                    │
                                    匯出 ONNX（訓練機評估用）＋ ncnn（板子用，權重 fp16）
                                                                    │
   板子（C++）：letterbox 640 ─▶ ncnn ─▶ 解碼 ─▶ 大圖切塊補小帽子 ─▶ NMS + 一人一框 ─▶ 存檔 + HDMI
```

訓練和評估在訓練機（有 GPU）做，板子只做推論。資料集（約 17 GB）、訓練與評估腳本、模型權重都不在這個 repo 裡；這裡只放板子上的程式和部署紀錄。

## A3. 選型

| 決定 | 選擇 | 原因 |
|---|---|---|
| 做法 | 直接偵測「戴著的安全帽」這一個類別 | 比「先找人、再判斷有沒有戴」少一個階段，板子上只要跑一個模型。「有沒有戴」交給訓練資料教（負樣本） |
| 模型 | YOLO26s | 一開始用最小的 YOLO26n（輸入 320）把流程走通。板子上跑一次 YOLO26s 約 5 秒，最大的照片也只要 34 秒，離 20 分鐘很遠，所以換成比較準的 s |
| 輸入大小 | 640×640 | 照片裡的帽子常常很小，輸入大一點比較看得到 |
| 推論引擎 | ncnn（C++） | 板子的 OpenCV 沒有 dnn、Python 沒有 cv2。ncnn 是純 CPU、支援 NEON，3.1 已經交叉編譯好 |
| 訓練工具 | Ultralytics | 訓練完可以直接匯出 ncnn 格式 |

## A4. 資料集

### 類別定義

只有一個類別 `helmet_worn`：任何保護頭部、而且**真的戴在頭上**的頭盔（工地、機車、自行車、運動、消防、軍用…）。框只框帽體（含硬質的下巴護具和面罩，不含臉、脖子、繫帶）。

下面這些都**不框**，而且刻意收進訓練集當負樣本：沒戴帽的人、拿在手上或放在桌上的安全帽、棒球帽、毛帽、草帽等一般帽子。

### 來源

| 內容 | 來源 | 張數 |
|---|---|---:|
| 基礎集：各類頭盔和負樣本 | Open Images、HelmetML（機車）、SHEL5K（工地） | 19,975 |
| 工地、工廠 | SHWD、HWD2024、SFCHD | 9,919 |
| 機車騎士 | HELMET（緬甸）、EdgeVision（印度） | 3,770 |
| 運動、軍用、馬術、消防等頭盔 | Open Images（有人工框的、只有影像標籤的）、COCO / LVIS | 7,155 |
| 戴一般帽子的人（負樣本） | Open Images、COCO / LVIS | 7,242 |
| 容易誤判的場景（幾乎都是負樣本） | Open Images 的運動和戶外人像、COCO 一般人像 | 9,954 |
| 合計 | | 58,015 |

58,015 張裡有 29,158 張有安全帽（共 49,675 個框），28,857 張完全沒有框。訓練當時是 58,264 張，之後遺失了 249 張。

授權：SHWD、HWD2024、SFCHD 三個來源沒有載明圖片授權，只當課程和研究用途，在清單裡另外標記；其餘是 CC BY、CC BY-SA 這類授權（不收禁止商用或禁止改作的圖）。

### 標註怎麼來的

各資料集原本的標法都不一樣（有的框整顆頭、有的連臉一起框、有的只有影像層級的標籤），所以全部轉成上面的定義。作法依來源分幾種：

| 來源的狀況 | 作法 |
|---|---|
| 有人工畫的頭盔框（Open Images） | 框的位置用人工框。請視覺語言模型（VLM，本機跑的 Qwen）逐框判斷「是不是戴在真人頭上」，再看整張圖有沒有漏掉的；框收緊到帽體。整張圖都是沒戴的頭盔，就變成負樣本 |
| 只有「這張圖有頭盔」的標籤，沒有框（Open Images） | VLM 先找出框，再逐框確認有戴，最後整張圖檢查一次 |
| 框的是「戴著安全帽的頭」，連臉一起框（SHWD、EdgeVision） | 把每個框裁出來放大，請 VLM 重新框到帽殼。必須剛好回一個框、而且落在原本的框裡，否則不收 |
| 框的就是帽體（HWD2024、SFCHD、SHEL5K、COCO / LVIS） | 只留「確實在某個人頭上」的帽子：帽子框要和標註的頭或人的頭部區域重疊 |
| 機車影片，標了每台車哪幾個座位有戴（HELMET） | VLM 出框，框數要剛好等於人工標的戴帽人數才收 |
| 負樣本 | 戴一般帽子的人、發布者標的沒戴帽的頭、沒戴的安全帽：整張圖沒有任何框 |

之後每個來源都要過三道檢查才會收進訓練集：

1. **交叉檢查**：用另外的偵測模型把候選圖掃一遍。模型很有把握這裡有安全帽、標註卻沒有，就可能是漏標，這張圖先隔離、不收（部分來源會再請 VLM 看裁切圖確認）。
2. **抽樣檢查**：每個來源分層抽大約 36 張（正樣本和負樣本都有）做成對照圖檢查，錯誤率 ≤ 10% 才收。實際收進來的各來源是 0%–8.3%。例如 EdgeVision 第一次抽 36 張錯了 4 張（框連臉一起框），沒有過；重新框到帽殼後才收。
3. **去重**：完全相同、同一組連拍、長得幾乎一樣（dHash，含左右鏡像）的圖只留一張，而且 train 不會和 val、test 重複。

要注意的是，**所有標註都不是逐張人工核實的**：來源是 VLM 的偽標籤或資料集發布者的標註，加上自動檢查和抽樣檢查。清單（manifest）裡每一筆都記成 `human_verified=false`。

| `eval_hats` | 441 | 2 | 戴一般帽子的人 | 量誤判 |
| `eval_oi` | 260 | 238 | 運動、軍用、馬術頭盔 | 量非工地頭盔的漏框 |
| test | 557 | 546 | 各來源混合 | 最後確認 |

每一輪都是先訓練、看錯在哪裡，再補對應的資料。

## A6. 照講義的規則評估、挑信心門檻

評估程式照講義的定義算：每個戴帽的目標最多算一個 TP；多出來的框、框到沒戴帽的人或背景都算 FP；漏掉的算 FN。預測框和標註框 IoU ≥ 0.5 才算框對（講義沒有定義，這是我們自己取的、偏嚴格的標準）。

評估時跑的是**和板子完全相同的流程**（整張 + 切塊 + 合併，A9），在訓練機上用 Python + ONNX 實作。

信心門檻 0.50 時的結果：

| 資料 | 張數 | TP / FP / FN | F1 |
|---|---:|---|---:|
| test | 557 | 671 / 27 / 35 | 0.956 |
| val 四組合併 | 2,561 | 2,675 / 146 / 104 | 0.955 |
| `val` | 503 | 623 / 18 / 37 | 0.958 |
| `eval_hwd2024`（工地） | 1,357 | 1,606 / 93 / 12 | 0.968 |
| `eval_oi`（運動 / 軍用頭盔） | 260 | 445 / 20 / 54 | 0.923 |
| `eval_hats`（一般帽子） | 441 | 1 / 15 / 1 | — |

- **門檻怎麼挑**：在 val 四組合併上從 0.15 掃到 0.75。F1 在 0.35–0.55 之間幾乎一樣（0.954–0.956）；0.50 時工地照片比低門檻好、一般帽子的誤框比較少，所以取 0.50。test 沒有參與。
- **`eval_hats` 不列 F1**：441 張裡只有 2 頂安全帽，F1 沒有意義。要看的是誤框：439 張沒有安全帽的圖，總共多框了 15 個。
- **IoU 0.5 偏嚴**：`val` 和 test 的標註多半是 Open Images 的原始框，常把整顆頭連臉一起框，而模型只框帽體，有些框對了但 IoU 不到 0.5。IoU 放寬到 0.3 時 test 是 0.960、`val` 是 0.967。

## A7. 錯誤分析與分數校正

把 FP 和 FN 逐個裁出來排成對照圖看（綠框是預測、藍框是標註），結論：

- 工地組的 FP 幾乎都是**有戴、但標註沒標到**的帽子（HWD2024 有一類「手扶著頭上的安全帽」在轉換時被捨棄），模型其實沒框錯。
- test 的錯誤大約一半是標註或框的畫法不同，不是真的看錯。
- 真正的弱點有兩種：分數偏低的運動頭盔（滑雪、機車、拳擊護具），和很小（約 25 px 以下）的帽子。

接著檢查模型的三個輸出尺度（80×80、40×40、20×20 格，分別負責小、中、大的帽子）。把每個尺度的分類 bias 各自從 0 掃到 +1.5，只有中間尺度有效：它的分數整體偏低，門檻 0.50 時有一批分數落在 0.3–0.5 的真帽子被漏掉。

所以訓練完之後多做一步**校正，沒有重新訓練**：把 `last.pt` 裡中間尺度分類輸出的 bias（`model.23.cv3.1.2.bias`，就一個數）從 −6.3047 改成 −5.5547。等於這個尺度的 logit 全部加 0.75（例如分數 0.40 變成 0.59），框的位置完全不變。加多少是在 val 上挑的，test 只用來確認。

| 資料（門檻 0.50） | 校正前 TP / FP / FN（F1） | 校正後 TP / FP / FN（F1） |
|---|---|---|
| test | 656 / 22 / 50（0.948） | 671 / 27 / 35（0.956） |
| val 四組合併 | 2,643 / 129 / 136（0.952） | 2,675 / 146 / 104（0.955） |
| `eval_oi`（運動 / 軍用頭盔） | 429 / 15 / 70（0.910） | 445 / 20 / 54（0.923） |
| `eval_hwd2024`（工地） | 1,604 / 86 / 14（0.970） | 1,606 / 93 / 12（0.968） |
| `eval_hats`（一般帽子） | 1 / 12 / 1 | 1 / 15 / 1 |

工地組多出的 7 個 FP，看圖後多半是上面說的沒標到的帽子。校正後的 `helmet.ncnn.bin` md5 是 `d809115f8b7fef28b033199aa991c3b2`；校正前是 `09b7c0e9ffb86d719f76262188300ab8`（`../helmet_work/stage6/MD5SUMS`）。兩個檔案只差這一個數值，`.param` 不變。

## A8. 匯出與驗證

`last.pt` 用 Ultralytics 匯出兩種格式：

| 格式 | 用途 | 說明 |
|---|---|---|
| ONNX（opset 12） | 訓練機上評估 | 用 OpenCV dnn 跑，算 A6 的 F1 |
| ncnn（`helmet.ncnn.param` + `.bin`） | 板子 | `.param` 是 320 層的網路結構（文字檔）；`.bin` 是權重，存成 fp16 所以只有 19 MB，載入時轉回 fp32 |

匯出的是**不含後處理**的版本：輸出是 5×8400 的表，每一欄是一個候選框 `(cx, cy, w, h, score)`。8400 = 80×80 + 40×40 + 20×20；只有一個類別，所以沒有類別那一維。去掉重複框（NMS）由我們的程式自己做，因為整張圖和切塊的結果本來就要合併。

換了格式、換了機器，結果有沒有變，分三段確認：

1. **ONNX 對 ncnn**（都在訓練機，ncnn 用 pyncnn 跑）：抽圖比對，分數差 ≤ 0.006、框差 ≤ 0.06 px。校正前的版本另外跑過整個 val，TP / FP / FN 完全相同。
2. **訓練機對板子**（同一個 ncnn 模型）：四張固定的測試圖（1024×683、1024×576、3000×2000、6000×4000），板子輸出的框和訓練機算的差 ≤ 0.1 px（2026-11-01）。預期輸出留在 `../helmet_work/stage*/expected.txt`。
3. **傳檔有沒有壞**：每次部署的檔案都附 `MD5SUMS`（`../helmet_work/stage*/`），傳到板子後核對。

## A9. 板子上的偵測流程

```
imread 照片（最大 6000×4000）
  └─ HelmetDetector::find_helmets
       ├─ detect(整張圖)          letterbox 到 640×640 → ncnn → 解出 (cx, cy, w, h, score) → 換回原圖座標
       ├─ detect(2×2 切塊各一次)   只收「小的」框（遠處的人），碰到切塊邊的丟掉
       └─ merge_boxes             NMS（IoU）→ 包含去重（一人一框）
  └─ draw_boxes → imwrite lab3_final_<組別>.jpg → sync → Framebuffer::show → 等 Enter
```

| 步驟 | 做什麼 | 為什麼 |
|---|---|---|
| letterbox | 等比例縮到最長邊 640，其餘補灰（114）成 640×640 | 和訓練時一樣，人不會被壓扁 |
| 解碼 | 8400 個候選框裡，分數 ≥ 0.50 的留下，座標先扣補邊、再除以縮放比，換回原圖 | 通常只剩個位數到幾十個 |
| 切塊 | 短邊 ≥ 1280 的照片再切 2×2 塊（相鄰重疊 20%），每塊各跑一次 | 6000×4000 縮到 640 後，遠處的帽子只剩幾個像素，模型看不到；切塊等於放大來看 |
| 切塊的框只收小的 | 框在「整張圖縮到 640」的尺度下小於 32 px 才收 | 近處的大頭，整張圖已經抓得到；切塊把它放大後反而容易誤判，也會多出重複框 |
| 切到邊的框丟掉 | 框貼到切塊的邊、而那條邊不是原圖的邊，就丟 | 帽子被切成一半，框不完整。重疊 20% 讓它在隔壁那塊是完整的 |
| NMS | 分數高的優先；和已保留的框 IoU > 0.45 就丟 | 同一頂帽子被整張圖和切塊各框一次 |
| 包含去重 | 小框有 70% 以上落在另一個框裡就丟 | IoU 不高、但其實是同一個人（例如一個框住整顆頭、一個只框帽子）。講義規定重複框算 FP |
| 存檔與顯示 | 原尺寸存 JPG、`sync()`、HDMI 等比例置中顯示、等 Enter | 圖片不可變形；確定寫進 SD 卡才拔；畫面要留給助教看 |

每一步在程式的哪裡，見下面的「程式碼地圖」和 [`CODE_GUIDE.md`](CODE_GUIDE.md)。

## A10. 試過但沒有採用的做法

| 做法 | 結果 |
|---|---|
| 切塊的框全部收，不限大小 | 近處的大頭放大後容易誤判，所以加了 `tile_max_box` |
| 原圖和左右翻轉各跑一次再合併（TTA） | F1 沒有進步，時間變兩倍 |
| 不重新訓練，把整個分類頭在固定的特徵上重新擬合 | test 沒有比只改一個 bias 好 |
| 把預測框整體放大或縮小 | 沒有進步 |
| 把運動 / 軍用頭盔那組驗證集併進訓練、非工地頭盔加倍取樣，再微調 12 個 epoch | test 0.947，沒有贏過原本的 0.948，只有併進去的那一組變好，所以不採用 |
| 同時用 2×2 和 4×4 兩種切塊（`../helmet_work/multi-scale-tiles.patch`） | 還沒有在板子上測過 |

## 參數（config.yml，不用重新編譯）

| 參數 | 值 | 說明 |
|---|---|---|
| `conf_threshold` | 0.50 | 信心門檻，在自備驗證集（val + eval_hwd2024 + 一般帽子 eval_hats）上 F1 最高的區間；正式測試圖沒有參與 |
| `nms_iou` | 0.45 | IoU 超過就當同一頂帽子的重複框 |
| `contain` | 0.70 | 小框 70% 以上落在另一框內 → 同一人重複框（重複框算 FP） |
| `tile_grid` | 2 | 短邊 ≥ 1280 的大圖再切 2×2 重疊塊各跑一次 |
| `tile_max_box` | 32 | 切塊只補「整張圖裡小於 32 px（模型尺度）」的遠處小帽子；近的大頭整張圖就抓得到，切塊放大後反而容易誤判 |
| `fb_device` | `/dev/fb2` | HDMI（`/dev/fb0` 是 LCD） |

Final demo 的測試圖是 6000×4000 的拼貼圖（很多張小照片拼在一起，每個人頭都很小），當天把 `tile_grid` 改成 4：
整張 + 4×4 切塊共 17 次推論，約 107 秒；框數從 2×2 的 71 個增加到 99 個。事前在同型的練習圖上逐框人工比對，
4×4 比 2×2 多 21 個正確框、少 4 個誤框。注意切塊條件是短邊 ≥ `tile_grid` × 640，所以 `tile_grid: 4` 只對短邊 ≥ 2560 的圖有效。
