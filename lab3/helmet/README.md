# A. 怎麼做的

## A1. 題目與設計

講義 3.2：給一張隱藏照片（JPG，最大 6000×4000），在板子上 20 分鐘內跑完，**只框有戴安全帽的人**，用 HDMI 顯示並存成 JPG。3.2.1 的分數 = 50 × F1。

| 條件 | 我們的作法 |
|---|---|
| 框到沒戴安全帽的人或背景，算 FP | 模型只學一個類別「戴在頭上的安全帽」。一般帽子、沒戴的安全帽、沒戴帽的人都當負樣本拿去訓練（A3） |
| 同一個人重複框，算 FP | NMS（重疊的框只留分數最高的）之後再去掉被包住的框，一人只留一框（A8） |
| 漏掉戴安全帽的人，算 FN；照片可能大到 6000×4000 | 大圖除了整張跑一次，再切塊各跑一次，補遠處的小帽子（A8） |
| 20 分鐘內跑完 | 速度不是問題，所以選比較準的 YOLO26s 和比較大的輸入 640（最小的 YOLO26n、輸入 320 是一開始用來試流程的） |
| 圖片不可變形 | 存檔用原尺寸；顯示時等比例縮放、置中 |
| 板子沒有 OpenCV dnn 和 Python cv2 | 推論用 ncnn（C++），3.1 已經交叉編譯好 |

## A2. 整體流程

```
公開資料集 ─▶ 統一成一個類別「戴在頭上的安全帽」─▶ 自動標註 + 檢查 ─▶ 訓練集 58k 張
                                                          │
                     val（挑門檻）、test（確認）◀──────────┤
                                                          ▼
                  訓練 YOLO26s（預訓練權重 → 輸入 640、60 epoch）
                      │        ▲
                      ▼        │ 補資料（共三輪）
            照講義規則算 F1、看錯誤
                      │
                      ▼
            信心門檻 0.50、校正分數 ─▶ 匯出 ONNX（訓練機評估用）＋ ncnn（板子用）
                      │
                      ▼
   板子（C++）：letterbox 640 ─▶ ncnn ─▶ 解碼 ─▶ 大圖切塊補小帽子 ─▶ NMS + 一人一框 ─▶ 存檔 + HDMI
```

訓練和評估在訓練機（有 GPU）做，板子只做推論。資料集（約 17 GB）、訓練與評估腳本、模型權重都不在這個 repo 裡；這裡只放板子上的程式和部署紀錄。

## A3. 資料集

### 類別定義

只有一個類別 `helmet_worn`：保護頭部、而且真的戴在頭上的頭盔都算（工地、機車、自行車、運動、消防、軍用…）。框只框帽體，不含臉、脖子、繫帶。

沒戴帽的人、拿在手上或放在桌上的安全帽、棒球帽和毛帽等一般帽子都不框。這些圖也收進訓練集當負樣本。

### 來源

| 內容 | 來源 | 張數 |
|---|---|---:|
| 基礎集：各類頭盔和負樣本 | Open Images、HelmetML（機車）、SHEL5K（工地）等 | 20,106 |
| 工地、工廠 | SHWD、HWD2024、SFCHD | 9,965 |
| 機車騎士 | HELMET（緬甸）、EdgeVision（印度） | 3,771 |
| 運動、軍用、馬術、消防等頭盔 | Open Images、COCO / LVIS | 7,210 |
| 戴一般帽子的人（負樣本） | Open Images、COCO / LVIS | 7,256 |
| 容易誤判的場景（幾乎都是負樣本） | Open Images 的運動和戶外人像、COCO 一般人像 | 9,956 |
| 合計 | | 58,264 |

其中 29,366 張有安全帽（共 50,187 個框），28,898 張完全沒有框。SHWD、HWD2024、SFCHD 三個來源沒有寫明圖片授權，只用在課程和研究；其餘幾乎都是 CC BY 這類授權。

### 標註怎麼來的

各資料集原本的標法都不一樣，所以全部轉成上面的定義。主要用訓練機上跑的視覺語言模型（VLM，Qwen）：

| 來源的狀況 | 作法 |
|---|---|
| 有人工畫的頭盔框（Open Images） | 請 VLM 逐框判斷「是不是戴在真人頭上」，再把框縮小到帽體。整張圖都是沒戴的頭盔，就變成負樣本 |
| 沒有框，只知道圖裡有頭盔或有人 | VLM 先找出框，再逐框確認有戴，最後整張圖檢查一次 |
| 框的是「戴著安全帽的頭」，或連臉一起框（SHWD、EdgeVision） | 把每個框裁出來放大，請 VLM 重新框到帽體 |
| 框的就是帽體（HWD2024、SFCHD、SHEL5K、COCO / LVIS） | 每個帽子框都要和資料集標的頭框（或人框的頭部區域）重疊，才算戴在頭上；有一頂對不上，整張圖就不收 |
| 機車影片，標了每台車哪幾個座位有戴（HELMET） | VLM 畫框，框數要剛好等於標註的戴帽人數才收 |
| 負樣本 | 戴一般帽子的人、沒戴帽的頭、沒戴的安全帽：整張圖沒有任何框 |

基礎集是最早整理的約 2 萬張，框主要由 VLM 產生，再由同一個 VLM 複查一次。之後加入的每個來源，要過三道檢查才收進訓練集：

1. 交叉檢查：用先前訓練出來的偵測模型掃一遍。模型很有把握有安全帽、標註卻沒有的圖，可能是漏標，不收。
2. 抽樣檢查：每個來源抽大約 36 張，把框畫在圖上看，錯誤率 ≤ 10% 才收。
3. 去重複：完全相同或幾乎一樣的圖只留一張；和驗證集、測試集重複或同一組連拍的圖不進訓練集。

這些標註來自 VLM 的偽標籤或資料集發布者，都沒有經過人工確認。上面的檢查（包含抽樣檢查）只決定一個來源收不收，不代表標註有人工核對過。

### 驗證集和測試集

都沒有參與訓練。標註一樣沒有經過人工確認（`val` 和 test 的框幾乎都是 VLM 畫的），所以 A5 的 F1 是和這份標註比出來的。

| 組 | 張數 | 內容 | 用途 |
|---|---:|---|---|
| `val` | 503 | 多數是運動和其他防護頭盔，少數工地和機車 | 一般情況 |
| `eval_hwd2024` | 1,357 | 工地照片，約一半是大圖 | 工地和大圖的情況 |
| `eval_hats` | 441 | 戴一般帽子的人（只有 2 頂安全帽） | 看誤判 |
| `eval_oi` | 260 | 運動、軍用、馬術頭盔 | 看工地以外的頭盔有沒有漏 |
| test | 557 | 和 `val` 同一批切出來 | 最後確認 |

上面四組驗證集用來挑信心門檻；test 不用來挑門檻。

## A4. 訓練 YOLO26s

### 作法

1. 準備資料設定檔：訓練清單 58,264 張，類別數 1。驗證清單是 `val` + `eval_hwd2024`，每個 epoch 結束用它算 mAP（偵測常用的平均精度）。標註是 YOLO 格式（每行 `0 cx cy w h`）。沒有安全帽的圖用空的標註檔，一樣進訓練。
2. 從預訓練權重開始：載入 Ultralytics 官方的 `yolo26s.pt`（在 COCO 80 類上訓練），把類別數改成 1。除了最後輸出類別分數的那幾層重新初始化，其他層都沿用預訓練權重。沒有凍結任何層，整個網路一起訓練。
3. 訓練 60 個 epoch，設定如下表。
4. 取最後一個 epoch 的權重（`last.pt`）。驗證分數從第 36 個 epoch 起就差不多了，分數最高的 epoch 和最後一個只差 0.001，所以不另外挑。

| 項目 | 設定 |
|---|---|
| 工具 | Ultralytics 8.4.193（PyTorch 2.13） |
| 輸入、批次 | 640×640、batch 12 |
| 優化器與學習率 | AdamW，學習率 0.001；前 3 個 epoch warmup，之後照 cosine 曲線降到約 1% |
| 資料增強 | mosaic（4 張拼成 1 張）、隨機縮放和平移、色彩抖動、左右翻轉。最後 10 個 epoch 關掉 mosaic，改用不拼接的單張圖訓練 |
| 其他 | 混合精度（AMP）、固定亂數種子；沒列出來的都用 Ultralytics 預設值 |
| 硬體與時間 | 一張 NVIDIA RTX PRO 6000 Blackwell（和標註用的 VLM 共用，所以 batch 保守取 12）；3 小時 |

```python
from ultralytics import YOLO

model = YOLO('yolo26s.pt')                 # COCO 預訓練權重
model.train(
    data='data_lab3.yaml',                 # 訓練清單、驗證清單、類別數 1
    imgsz=640, epochs=60, batch=12,
    optimizer='AdamW', lr0=0.001, cos_lr=True,
    close_mosaic=10,                       # 最後 10 個 epoch 關 mosaic
    amp=True, seed=20261031,
)
```

訓練結束時，驗證清單上的 mAP50 是 0.983、mAP50-95 是 0.803。

### 三輪訓練：看錯誤、補資料

三輪的訓練設定完全相同，只有資料不同；每一輪都從同一份預訓練權重重新開始。

| 輪 | 訓練張數 | 上一輪看到的問題 → 這一輪補的資料 | 結果（講義規則的 F1，校正前；第 1 輪門檻 0.55，之後 0.50） |
|---|---:|---|---|
| 1 | 33,617 | 起點：基礎集加上工地、機車等來源 | 工地 0.973；但戴一般帽子的那組照片誤框了 208 個 |
| 2 | 50,985 | 一般帽子被當成安全帽 → 加入戴一般帽子的人、容易誤判的場景當負樣本 | 一般帽子誤框 208 → 10，工地持平；但開始漏掉棒球打擊頭盔、馬術帽這類長得像帽子的頭盔 |
| 3 | 58,264 | 漏掉運動和軍用頭盔 → 主要加入 Open Images 人工框的各類頭盔（VLM 確認有戴、框縮小） | 運動 / 軍用組 0.852 → 0.910，工地持平，一般帽子誤框 10 → 12 |

三輪的 mAP 幾乎一樣（mAP50 都是 0.98），上面這些問題在 mAP 上看不出來，要照講義的規則算 F1（A5）、把錯的框拿出來看才看得到。所以另外留了一般帽子、運動頭盔這兩組驗證集來量。test 的 F1 三輪也差不多（0.955、0.951、0.948）。

## A5. 照講義的規則評估、挑信心門檻

評估程式照講義的定義算：每個戴帽的人最多算一個 TP；多出來的框、框到沒戴帽的人或背景都算 FP；漏掉的算 FN。預測框和標註框的 IoU（交集 ÷ 聯集）≥ 0.5 才算框對；講義沒有定義，這是我們自己取的標準。評估時跑的是和板子相同的流程（整張 + 切塊 + 合併，A8），在訓練機上用 Python + ONNX 實作。

最終模型（第 3 輪的權重加上 A6 的分數校正）在信心門檻 0.50 的結果：

| 資料 | 張數 | TP / FP / FN | F1 |
|---|---:|---|---:|
| test | 557 | 671 / 27 / 35 | 0.956 |
| 驗證四組合併 | 2,561 | 2,675 / 146 / 104 | 0.955 |
| `val` | 503 | 623 / 18 / 37 | 0.958 |
| `eval_hwd2024`（工地） | 1,357 | 1,606 / 93 / 12 | 0.968 |
| `eval_oi`（運動 / 軍用頭盔） | 260 | 445 / 20 / 54 | 0.923 |
| `eval_hats`（一般帽子） | 441 | 1 / 15 / 1 | — |

信心門檻是用四組驗證集從 0.15 試到 0.75 挑的。合併的 F1 在 0.35–0.55 之間幾乎一樣；0.50 時工地照片比低門檻好、一般帽子的誤框比較少，所以用 0.50。

`eval_hats` 的 441 張裡只有 2 頂安全帽，不列 F1，只看誤框：439 張沒有安全帽的圖總共多框了 15 個。

## A6. 分數校正

模型有三個輸出尺度（80×80、40×40、20×20 格），格子越細負責越小的帽子。訓練完之後，我們把某個尺度分類輸出的 bias 加一個常數，等於那個尺度所有候選框的分數一起調高，再到驗證集上重新算 F1。只有中間的 40×40 尺度有明顯幫助。

所以把 `last.pt` 裡這一個 bias 加 0.75，重新匯出。沒有重新訓練，框的位置不變。

| 資料（門檻 0.50） | 校正前 TP / FP / FN（F1） | 校正後 TP / FP / FN（F1） |
|---|---|---|
| test | 656 / 22 / 50（0.948） | 671 / 27 / 35（0.956） |
| 驗證四組合併 | 2,643 / 129 / 136（0.952） | 2,675 / 146 / 104（0.955） |

這個效果和把門檻放低差不多：不校正、只把門檻降到 0.35，test 也有 0.955，校正只多約 0.001。

校正後的 `helmet.ncnn.bin`（md5 `d809115f8b7fef28b033199aa991c3b2`）和校正前的檔只差這一個數值，`.param` 不變。`../helmet_work/stage6/MD5SUMS` 記的是校正前那個檔。

## A7. 匯出與驗證

```python
from ultralytics import YOLO
YOLO('last.pt').export(format='onnx', imgsz=640, opset=12, simplify=True, nms=False, end2end=False, device='cpu')   # 訓練機評估用
YOLO('last.pt').export(format='ncnn', imgsz=640, half=True, device='cpu')                                         # 板子用
```

- ncnn 的 `.param` 是網路結構（文字檔），`.bin` 是權重。`half=True` 把權重存成 fp16，所以只有 19 MB，載入時轉回 fp32。
- 匯出的模型不含後處理：輸出是 5×8400 的表，每一欄是一個候選框 `(cx, cy, w, h, score)`，8400 = 80×80 + 40×40 + 20×20。同一頂帽子會有好幾個候選框，去掉重複框（NMS）由我們的程式自己做，因為整張圖和切塊的結果本來就要合併。

換格式、換機器後結果有沒有變，分三段確認：

1. ONNX 對 ncnn（都在訓練機跑）：整個 test 557 張，門檻 0.50 的 TP / FP / FN 完全相同。
2. 訓練機對板子（同一個 ncnn 模型檔）：四張固定的測試圖（最大 6000×4000），板子輸出的框和訓練機算的差 ≤ 0.1 px。這是 11/1 用校正前的權重測的。預期輸出留在 `../helmet_work/stage*/expected.txt`。
3. 傳檔有沒有壞：用序列埠傳到板子的執行檔、設定和模型都附 `MD5SUMS`（`../helmet_work/stage*/`），傳完在板子上核對。

## A8. 板子上的偵測流程

```
imread 照片（最大 6000×4000）
  └─ HelmetDetector::find_helmets
       ├─ detect(整張圖)          letterbox 到 640×640 → ncnn → 解出 (cx, cy, w, h, score) → 換回原圖座標
       ├─ detect(2×2 切塊各一次)   只收「小的」框（遠處的人），碰到切塊邊的丟掉
       └─ merge_boxes             NMS（IoU）→ 去掉被包住的框（一人一框）
  └─ draw_boxes → imwrite lab3_final_<組別>.jpg → sync → Framebuffer::show → 等 Enter
```

| 步驟 | 做什麼 | 為什麼 |
|---|---|---|
| letterbox | 等比例縮到最長邊 640，其餘補灰（114）成 640×640 | 人不會被壓扁 |
| 解碼 | 8400 個候選框裡，分數 ≥ 0.50 的留下，座標先扣補邊、再除以縮放比，換回原圖 | 通常只剩個位數到幾十個 |
| 切塊 | 短邊 ≥ 1280 的照片再切 2×2 塊（相鄰重疊 20%），每塊各跑一次 | 6000×4000 縮到 640 後，遠處的帽子只剩幾個像素，模型看不到；切塊等於放大來看 |
| 切塊的框只收小的 | 框在整張圖縮到 640 時小於 32 px 才收 | 近處的大頭，整張圖已經抓得到；切塊把它放大後反而容易誤判 |
| 切到邊的框丟掉 | 框貼到切塊的邊、而那條邊不是原圖的邊，就丟 | 帽子被切成一半，框不完整。重疊 20% 讓它在隔壁那塊是完整的 |
| NMS | 分數高的優先；和已保留的框 IoU > 0.45 就丟 | 同一頂帽子有好幾個候選框，也會被整張圖和切塊各框一次 |
| 一人一框 | 兩個框的交集超過較小那個框面積的 70%，就丟掉分數低的那個 | IoU 不高、但其實是同一個人（例如一個框住整顆頭、一個只框帽子）。講義規定重複框算 FP |
| 存檔與顯示 | 原尺寸存 JPG、`sync()`、HDMI 等比例置中顯示、等 Enter | 圖片不可變形；確定寫進 SD 卡才拔；畫面要留給助教看 |

上表是預設（`tile_grid: 2`），這份文件的 F1 都是用它量的；Demo 當天改成 4×4（見 B 的「參數」）。

每一步在程式的哪裡，見下面的「程式碼地圖」和 [`CODE_GUIDE.md`](CODE_GUIDE.md)。

## 參數（config.yml，不用重新編譯）

| 參數 | 值 | 說明 |
|---|---|---|
| `conf_threshold` | 0.50 | 信心門檻，在自備驗證集上 F1 差不多的區間裡取的（A5）；Demo 的隱藏照片沒有參與 |
| `nms_iou` | 0.45 | IoU 超過就當同一頂帽子的重複框 |
| `contain` | 0.70 | 小框 70% 以上落在另一框內 → 同一人重複框（重複框算 FP） |
| `tile_grid` | 2 | 短邊 ≥ 1280 的大圖再切 2×2 重疊塊各跑一次 |
| `tile_max_box` | 32 | 切塊只補「整張圖裡小於 32 px（模型尺度）」的遠處小帽子；近的大頭整張圖就抓得到，切塊放大後反而容易誤判 |
| `fb_device` | `/dev/fb2` | HDMI（`/dev/fb0` 是 LCD） |

Final demo 的測試圖是 6000×4000 的拼貼圖（很多張小照片拼在一起，每個人頭都很小），當天把 `tile_grid` 改成 4：
整張 + 4×4 切塊共 17 次推論，約 107 秒；框數從 2×2 的 71 個增加到 99 個。事前在同型的練習圖上逐框人工比對，
4×4 比 2×2 多 21 個正確框、少 4 個誤框。注意切塊條件是短邊 ≥ `tile_grid` × 640，所以 `tile_grid: 4` 只對短邊 ≥ 2560 的圖有效。
