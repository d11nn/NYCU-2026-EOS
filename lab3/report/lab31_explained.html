Lab 3.1 即時人臉辨識：怎麼實作的

每一幀畫面從 camera.cpp 進來，經過 Haar 找臉、追蹤、MobileFaceNet 辨識、投票，最後畫上框和學號輸出到 HDMI。這頁整理了 3.1 的所有技術內容：一分鐘摘要、逐步流程動畫與實際程式碼、設計理由、助教問題速查、參數、建置部署與遇到的問題。

camera→ Haar 偵測→ 追蹤→ 送辨識→ 對齊＋MobileFaceNet＋比對→ 投票→ 畫框＋輸出
先講這段

一分鐘講完：我們怎麼做 3.1

  1. 限制：E9V3 只有 4 核 Cortex‑A9，沒有 NPU；Lab 2 編的 OpenCV 3.4 沒有 dnn 模組；每位組員只有約 20 張照片，不可能自己訓練模型。
  2. 偵測：用 OpenCV 內建的 Haar cascade 找臉。畫面先轉灰階、縮到 320 寬、做直方圖等化再偵測，重疊的框合併成一個。
  3. 辨識：用預訓練的 MobileFaceNet（手機用的小型 CNN），透過自己交叉編譯的 ncnn 執行。臉先用眼睛位置轉正成 112×112，模型輸出 128 維特徵。
  4. 判斷：跟兩位組員的範本（登錄照片特徵的平均）算 cosine 相似度。最高分 ≥ 0.45 而且贏第二名 0.08 才顯示學號，否則 unknown。不用分類器，因為陌生人沒辦法事先收集。
  5. 穩定：追蹤器跨幀配對同一張臉（IoU 或中心距離）、平滑框座標、沒偵測到時保留 0.4 秒；標籤用最近 7 次結果多數決，所以不抖、不閃。
  6. 速度：三個執行緒：攝影機只留最新畫面、主迴圈負責偵測和顯示、辨識放背景。輸出到 HDMI（/dev/fb2，32 bpp），等比例置中不變形。
逐步流程與程式碼為什麼這樣選助教問題速查門檻試算參數總表建置與部署遇到的問題檔案地圖

Design decisions

為什麼這樣選

決定選了什麼為什麼沒選的
偵測Haar cascade板上 OpenCV 3.4 已經有 objdetect，不用裝任何東西；速度快。缺點（只認正臉、偶爾誤判）用追蹤和投票彌補YuNet / libfacedetection（更準，但要多編一個函式庫）、MTCNN（三張臉時太慢）、YOLO（A9 跑不動）
辨識MobileFaceNet（預訓練）為手機設計，參數不到 100 萬、LFW 99.55%。特徵分得開，才能用門檻判斷 unknownLBPH（光線、角度敏感，門檻難設）、FaceNet / ArcFace（太大太慢）、OpenFace（準度較低，且需要 dnn）
推論框架ncnn板上的 libopencv_world.so.3.4 用 grep 查過沒有 dnn 符號。ncnn 專為 ARM 手機最佳化，不用動 Lab 2 已經能用的 OpenCV重編 OpenCV 開 dnn（耗時、要動既有環境）
判斷學號 / unknown相似度 + 門檻unknown 是「所有沒看過的人」，分類器一定會從訓練過的類別挑一個；門檻法不夠像就是 unknown三類分類器（unknown 類收集不完）
資料只登錄、不訓練每人約 20 張照片，訓練或 fine‑tune 都會過擬合。照片只用來算範本和校準門檻從頭訓練、fine‑tune
穩定追蹤 + 投票講義 3.1.3 要求框和標籤不抖不閃；Haar 每幀獨立，必須跨幀整合每幀直接畫偵測結果
顯示原尺寸置中（display_fit: 0）放大到 1080p 每幀要寫約 6 MB，FPS 下降會造成延遲和殘影；原尺寸只要約 1.2 MB。講義沒有規定畫面大小放大到全螢幕、改 HDMI 解析度

Gallery::match

學號還是 unknown：門檻怎麼決定

MobileFaceNet 把每張臉變成 128 個數字。程式把它跟兩位組員的「範本」（登錄照片的平均）算 cosine 相似度：越接近 1 越像。最高分夠高、而且明顯贏過第二名，才顯示學號；否則一律是 unknown。拉動門檻看看判斷怎麼變。

實測（登錄照片）：314831017 跟自己範本平均 0.909、最低 0.766；314581047 平均 0.863。兩位組員彼此最高只有 0.089。所以 0.45 落在中間，兩邊都留了很大的空間。

Build & deploy

建置與部署：三台機器

Mac

寫程式碼，用 scp -O 傳到 Ubuntu。

Ubuntu（x86）

用 arm-linux-gnueabihf-g++（gcc‑linaro 5.3）交叉編譯：先用 scripts/build_ncnn.sh 編 ncnn，再 make OPENCV_DIR=/usr/local/arm-opencv/install。產生的 face3 是 ARM 執行檔，只能在板子上跑。

E9V3（ARM）

放 face3、config.yml、models/、libopencv_world.so.3.4、libgomp.so.1，用 run.sh（LD_LIBRARY_PATH=.）執行，跟 Lab 2 的 demo.sh 一樣。

指令（在板子上）做什麼
./run.sh enroll enroll讀 enroll/<學號>/*.bmp，建立 gallery.yml，印出相似度統計
./run.sh score strangers每張照片印出最像誰、相似度多少，用來校準門檻
./run.sh run 2>&1 | grep -v "Corrupt JPEG"即時辨識；每 30 幀印出 FPS、各階段耗時、延遲
Problems we hit

遇到的問題與解決

問題原因解決
OpenCV 不能跑神經網路Lab 2 編的 world 函式庫沒有 dnn（grep -c _ZN2cv3dnn 是 0）另外交叉編譯 ncnn
連結時大量 Qt undefined referenceLab 2 的 OpenCV 開了 Qt highgui，Ubuntu 上沒有 ARM 版 QtMakefile 加 -Wl,--allow-shlib-undefined，執行時由板子上的 Qt5 解析
終端機一直印 Corrupt JPEG dataUSB 攝影機的 MJPG 每幀多幾個 byte，libjpeg 略過並警告，影像正常執行時用 grep -v 過濾
接了 HDMI 沒畫面板子 LCD 和 HDMI 同時輸出，HDMI 是 /dev/fb2，不是 fb0從 /proc/cmdline 和 /sys/class/graphics/ 找到 fb2，改 config
HDMI 畫面延遲、同一人多個框、背景殘留學號放大到 1080p 讓 FPS 下降 → 人在兩幀之間移動太遠，配對失敗產生新框；舊框又用「幀數」保留好幾秒原尺寸顯示；配對加中心距離；保留改用秒數；大幅移動直接跳；合併重疊框
一張登錄照片相似度只有 0.364Haar 在側臉或背景上誤判，眼睛也是估計的用 score 找出那張（10.bmp）並刪除
在 Ubuntu 上執行 face3 出現 Syntax errorface3 是 ARM 執行檔，x86 跑不動，shell 把它當腳本讀一定要在板子上執行
